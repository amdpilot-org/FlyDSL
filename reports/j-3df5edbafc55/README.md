# Independent review of PR 615

Reviewed `https://github.com/amdpilot-org/FlyDSL/pull/615` at exact commit
`dc5fe72c768515f3987cbc8e879d4ae37eb36285` against upstream issue
`https://github.com/ROCm/FlyDSL/issues/862` and mirror issue
`https://github.com/amdpilot-org/FlyDSL/issues/616`.

## Verdict

Accept as a verified partial optimization, not as a full resolution of the
original compile-time issue. The candidate removes one redundant MLIR
serialization in the normal JIT path and its focused regression fails on base
and passes on the candidate. It correctly narrows its own claim. It does not
demonstrate a general or statistically supported cold end-to-end speedup.

The base regression failed with `TypeError` because `MlirCompiler.compile` did
not accept retained `source_ir`; the candidate's focused and cache tests passed
(20 tests). Three distinct fresh-cache GPU runs per revision produced identical
cache-key, source-IR, and compiled-IR hashes and matched independent Torch
references. Median wall/compiler times in milliseconds were:

| workload | base wall | candidate wall | base compiler | candidate compiler |
|---|---:|---:|---:|---:|
| RMSNorm 16x4096 | 146.78 | 147.34 | 82.98 | 83.59 |
| GEMM 1024^3 | 720.08 | 709.64 | 233.18 | 226.77 |

These small mixed deltas are compatible with run-to-run noise. The saved source
text parse alone took roughly 2.3--2.9 ms for RMSNorm and usually 9.1--9.2 ms
for GEMM (one 23 ms outlier), while most pipeline time remains.

## Independent adversarial findings

The retained artifact text is always produced with `enable_debug_info=True`,
whereas the prior compiler-side serialization obeyed
`env.debug.enable_debug_info` (false by default). A focused probe confirms that
the candidate parses the supplied always-debug text and skips the configured
serialization. The tested workloads still generated byte-identical final IR,
but the new regression does not cover this input-policy distinction. This is a
minor review limitation rather than a demonstrated correctness regression.

The exact issue-linked branch resolves to remote branch `xiaobing/bench` at
`61e048653db47113c736afeb336851f98cc7c5c4`. Its RMSNorm kernel imports removed
`flydsl.expr.vector` APIs and fails during import against this checkout.
Therefore the reporter's exact workload could not be executed and was not
replaced with the maintained smoke in the verdict.

## Environment

GPU execution used one AMD Instinct MI350X with
`gfx950:sramecc+:xnack-`, not the reported MI355. Python source imported from
`/job/repo/python`; the MLIR Python/native extension imported from the prepared
checkout under `/job/repo/python/flydsl/_mlir`. PR 615 contains no C/C++/TableGen
changes, so a native rebuild was neither required nor performed. Torch was
`2.9.1+rocm7.2.0.git7e1940d4`, with HIP `7.2.26015-fc0010cf6a`.

Raw logs, exit codes, path evidence, the adversarial probe, the fetched linked
`run.sh`, and the aggregate timing summary are retained in `raw/`.
